## 1. 개요

### 1.1 서비스 한 줄 소개
관심 기업을 검색하면 재무제표·시세·뉴스·사업보고서를 바탕으로 **AI가 쉬운 말로 풀어 쓴 핵심 분석**을 보여주는 주식 초보자(10대 포함)용 서비스.

### 1.2 핵심 원칙 (변경 없음)
1. 어려운 재무 정보를 쉬운 말로
2. 숫자는 공식 자료 그대로, AI는 설명만
3. 투자 추천이 아니라 이해를 돕는다
4. 숫자보다 문장

### 1.3 이번 개정의 핵심 변화
- **기업 상세 화면의 축이 "차트 먼저 보기"에서 "AI 핵심 분석 먼저 보기"로 바뀜.** 예전엔 차트 탭이 기본이고 리포트는 버튼을 눌러야 보였는데, 지금은 **개요 탭을 열면 AI 분석이 곧바로 보임** (단, 생성 자체는 여전히 버튼으로 시작)
- 홈 화면이 "많이 보는 회사 목록 1개"에서 **4단 대시보드**(거래 많은 기업/떠오르는 기업/관심도 높은 기업/AI가 분석한 기업)로 확장
- 리포트 응답 형식이 "요약+그래프 선택+장단점"에서 **"5개 고정 카테고리 핵심 포인트(before/after 비교)"**로 재설계
- 광고 자리(AdSlot), 용어 게임, 커뮤니티 탭(자리만)이 새로 추가됨

### 1.4 범위
| 구분 | 내용 |
|---|---|
| MVP 포함 | 기업 검색, 홈 대시보드, AI 핵심 분석(개요), 재무 상세, 뉴스 상세, 기업 정보, 퀴즈, 용어 설명, 용어 카드/게임, 관심 기업, 로그인, 광고 자리 |
| MVP 제외 (자리만 구현) | 커뮤니티 — 탭은 있지만 "준비 중" 안내만 표시 |
| MVP 제외 (완전 미구현) | 모의투자, 알림, 패스키 로그인 |

## 2. 사용자와 용어

| 용어 | 의미 |
|---|---|
| 확인된 값 | DART·한국거래소·회사 공식 실적 발표로 확인한 숫자 |
| 예시 값 | 아직 확인하지 않아 임시로 넣은 숫자. `is_sample: true`, 화면에 "예시 값" 배지 |
| 핵심 포인트 (key_points) | AI 분석의 기본 단위. 항상 5개, 항상 같은 순서 (§5 F-04 참고) |

## 5. 기능 상세 (바뀐 것 위주로)

### F-02 홈 대시보드 🆕

| 항목 | 내용 |
|---|---|
| 설명 | 홈 화면이 검색창 + 단일 목록에서 4단 섹션으로 확장됨 |
| 섹션 구성 | ① 오늘 거래가 많은 기업(거래대금 기준) ② 떠오르는 기업(기준 미정) ③ 관심도 높은 기업(집계 기준 미정) ④ AI가 분석한 기업(리포트 완료된 회사만) |
| 광고 | ②와 ③ 섹션 사이에 광고 자리 1개 |
| API | `GET /api/home` (백엔드 미구현 — API_SPEC.md §3 참고) |
| 수용 기준 | - [ ] 리포트가 없는 회사는 "AI가 분석한 기업" 섹션에 안 나온다<br>- [ ] 떠오르는 기업/관심도 높은 기업의 `criteria` 문구가 화면에 그대로 보인다 |

**미결 사항**: "떠오르는 기업"과 "관심도 높은 기업"의 선정 기준이 아직 정해지지 않음 (§8 참고).

### F-04 AI 핵심 분석 (개요) 🔁 전면 재설계

| 항목 | 내용 |
|---|---|
| 설명 | 기업 상세를 열면 가장 먼저, 가장 크게 AI 핵심 분석이 보임 |
| 상태 | `none`(없음) → `generating`(만드는 중) → `done`(완료) / `failed`(실패). 재생성 중·실패해도 **이전 리포트 내용을 화면에서 지우지 않음** |
| 트리거 | "AI 리포트 만들기" 버튼 (최초), "다시 만들기" 버튼 (재생성) |
| 진행 표시 | `ReportProgress` 컴포넌트 — 예상 소요 시간 15초 안내, 취소 가능 |
| 폴링 | 생성 중엔 2초 간격으로 `GET`을 다시 불러서 상태 확인 (`refetchInterval`) |
| 실패 처리 | 최초 생성 실패 → 실패 카드 + 원인 문구 + "다시 시도" 버튼<br>재생성 실패 → 기존 리포트는 그대로 두고 토스트로만 안내 ("리포트를 다시 만들지 못했어요. 기존 리포트를 보여드릴게요.") |
| API | `GET/POST /api/companies/{stock_code}/report` (스키마 전면 변경 — API_SPEC.md §5) |

**핵심 포인트 5가지 (고정 순서)**

| 순서 | category | 화면 라벨 |
|---|---|---|
| 1 | `performance` | 실적 특징 |
| 2 | `revenue_source` | 주요 수익원 |
| 3 | `recent_change` | 최근 실적 변화 |
| 4 | `risk` | 위험·변화 요인 |
| 5 | `strength` | 핵심 경쟁력 |

각 포인트는 `title`(한 줄 결론), `before`/`after`(비교 수치, 없으면 `null`), `reason`(왜 그런가요, 1~2문장), `meaning`(무슨 뜻인가요, 1문장), `evidence`(근거 자료 종류)로 구성됩니다. 백엔드가 순서를 다르게 보내도 프론트가 위 순서로 재정렬하고, 모르는 category는 맨 뒤로 보냅니다.

**수용 기준**
- [ ] 기업 화면을 열기만 해서는 리포트가 생성되지 않는다
- [ ] 생성 중 화면을 나갔다가 들어와도 진행 상황이 유지된다 (폴링으로 이어받음)
- [ ] 재생성이 실패해도 이전 리포트가 계속 보인다

### F-05/F-06 핵심 그래프 · 근거 자료 🆕

| 항목 | 내용 |
|---|---|
| 설명 | 예전엔 AI가 "어떤 그래프를 넣을지" 골랐는데(`charts[]`), 이제는 **근거 자료(`evidence.financials`)의 원본 배열로 프론트가 직접 그래프를 그림** |
| 근거 자료 3종 | `financials`(연도별 매출·영업이익, 하이라이트), `news`(실제 기사), `vision`(회사 비전, 사업부문별 매출 구성) |
| 빈 데이터 처리 | 셋 중 하나가 없어도(`null` 또는 빈 배열) 그 칸에만 "자료를 찾지 못했어요" 표시, 화면 전체는 안 깨짐 |
| 이동 | 핵심 포인트의 "근거 보기"를 누르면 해당 근거 자료 위치로 스크롤하거나, 근거가 없으면 관련 상세 탭(재무/뉴스/기업정보)으로 이동 |
